# راهنمای ارتقای یکپارچه از نسخه ۵.۰.۰ به ۵.۰.۳

این بسته شامل تمام اصلاحات نسخه‌های ۵.۰.۱، ۵.۰.۲ و ۵.۰.۳ است و مستقیماً از نسخه یکپارچه ۵.۰.۰ قابل انتشار است. لازم نیست ابتدا بسته‌های ۵.۰.۱ یا ۵.۰.۲ را جداگانه نصب کنید.

## پیش‌نیاز

این راهنما با این فرض نوشته شده است که:

- فایل‌های برنامه در حال حاضر بر مبنای نسخه ۵.۰.۰ هستند.
- مهاجرت پایه `supabase/5.0.0_modules_attendance.sql` قبلاً در پروژه Supabase اجرا شده است.
- فایل `config.js` فعلی و تنظیمات اتصال Supabase معتبر هستند.

اگر مهاجرت پایه نسخه ۵.۰.۰ هنوز اجرا نشده است، ابتدا همان فایل را اجرا کنید و سپس مراحل زیر را ادامه دهید.

## خلاصه تغییرات تجمعی

### تغییرات نسخه ۵.۰.۱

1. بازطراحی رابط درگاه انتخاب ماژول برای نمایش بهتر در موبایل و دسکتاپ.
2. پس از ثبت موفق اقدام در ماژول ثبت فعالیت، کاربر بین دو گزینه «ثبت اقدام بعدی» و «رفتن به صفحه تقویم» انتخاب می‌کند.
3. ساعت شروع و پایان در فرم ثبت عدم حضور برای تمام انواع رویداد نمایش داده می‌شود.
4. برای «مرخصی ساعتی» هر دو ساعت اجباری است؛ برای سایر انواع رویداد ثبت هر دو ساعت اختیاری است. ثبت یکی از دو ساعت به‌تنهایی پذیرفته نمی‌شود.
5. دو رویداد زمان‌دار در یک روز، در صورت نداشتن هم‌پوشانی، قابل ثبت هستند.
6. رویدادهای پنجشنبه، جمعه و تعطیلات نیز در گزارش به‌عنوان روزهای تقویمی رویداد محاسبه می‌شوند.
7. شاخص‌های «روزهای کاری دوره» و «حضور عادی» از داشبورد، جزئیات افراد و خروجی CSV حذف شده‌اند.

### تغییرات نسخه ۵.۰.۲

عنوان دکمه بازکردن تقویم در پنجره نتیجه ثبت اقدام از «رفتن به صفحه تقویم» به «مشاهده تقویم» تغییر کرده است. عملکرد دکمه ثابت است و تقویم ماه مربوط به اقدام را باز می‌کند.

### تغییرات نسخه ۵.۰.۳

1. فقط برای حسابی که شماره پرسنلی آن `۹۵۸۰۰۱` است، شخص دارای شماره پرسنلی `۷۸۴۹۵` در فرم جدید ثبت فعالیت ماهانه به‌صورت پیش‌فرض انتخاب می‌شود.
2. حساب ۹۵۸۰۰۱ می‌تواند انتخاب پیش‌فرض را بردارد، خودش یا هر شخص دیگری را انتخاب کند.
3. در حالت ویرایش، شرکت‌کنندگان ذخیره‌شده قبلی حفظ می‌شوند.
4. سایر کاربران و سایر بخش‌های برنامه بدون تغییر باقی می‌مانند.
5. شناسه ثبت‌کننده واقعی (`createdBy`) همچنان متعلق به حساب واردشده، یعنی ۹۵۸۰۰۱، است. این تغییر نقش یا مجوز مدیریتی جدیدی ایجاد نمی‌کند.

## مراحل انتشار فایل‌های برنامه

1. از مخزن GitHub و پایگاه داده Supabase نسخه پشتیبان تهیه کنید.
2. محتویات این بسته را با حفظ ساختار پوشه‌ها در مخزن/میزبانی فعلی جایگزین کنید.
3. فایل `config.js` فعلی را حفظ کنید؛ این فایل در بسته قرار ندارد و نباید حذف یا با فایل دیگری جایگزین شود.
4. فایل `sw.js` منتشرشده فعلی را نیز حفظ کنید و فقط مطابق بخش «ارتقای نسخه کش» در پایین، دو مقدار نسخه را دستی تغییر دهید. فایل `sw.js` داخل ZIP عمداً به‌روزرسانی نشده است.
5. مطمئن شوید فایل‌های `Activity.html`، `index.html`، `manifest.json`، پوشه `assets` و پوشه `icons` در مسیرهای صحیح قرار گرفته‌اند.

## مهاجرت دیتابیس از ۵.۰.۰ به ۵.۰.۳

با فرض اینکه مهاجرت پایه نسخه ۵.۰.۰ قبلاً اجرا شده است:

1. فقط فایل زیر را در SQL Editor همان پروژه Supabase اجرا کنید:

   `supabase/5.0.1_attendance_time_fields.sql`

2. این مهاجرت، محدودیت‌های ساعت رویدادهای عدم حضور و کنترل هم‌پوشانی رویدادهای زمان‌دار را به‌روزرسانی می‌کند.
3. برای نسخه‌های ۵.۰.۲ و ۵.۰.۳ هیچ مهاجرت SQL دیگری وجود ندارد.
4. فایل `supabase/5.0.0_modules_attendance.sql` را دوباره اجرا نکنید؛ آن فایل فقط برای نصب پایه نسخه ۵.۰.۰ است.

اگر قبلاً مهاجرت `5.0.1_attendance_time_fields.sql` را اجرا کرده‌اید، نیازی به اجرای مجدد آن نیست.

## ارتقای نسخه کش PWA

در فایل `sw.js` موجود در مخزن منتشرشده، این مقادیر را دستی تغییر دهید:

```js
/* نسخه: actbk-v5.0.3 */
const CACHE_VERSION = 'Ver-5.0.3';
```

خط `CACHE_NAME` باید همچنان از `CACHE_VERSION` ساخته شود. سایر منطق فایل Service Worker را تغییر ندهید.

## بازگشت در صورت بروز مشکل

پیش از انتشار، نسخه قبلی فایل‌های برنامه و پشتیبان دیتابیس را نگه دارید. اگر رابط کاربری دچار مشکل شد، فایل‌های نسخه ۵.۰.۰ را بازگردانید و نسخه کش Service Worker را به یک مقدار جدید و یکتا تغییر دهید تا کش نسخه معیوب دوباره استفاده نشود. اگر مهاجرت SQL اجرا شده باشد، پیش از بازگرداندن دیتابیس، وضعیت تغییرات schema را بررسی کنید؛ صرفاً بازگرداندن فایل‌های Frontend، مهاجرت دیتابیس را معکوس نمی‌کند.
