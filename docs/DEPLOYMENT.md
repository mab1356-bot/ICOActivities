# راهنمای عمومی انتشار

1. پیش از هر انتشار از مخزن GitHub و دیتابیس نسخه پشتیبان تهیه کنید.
2. فایل‌های بسته را با حفظ ساختار پوشه‌ها در مخزن جایگزین کنید.
3. فایل `config.js` محیط عملیاتی را حفظ کنید؛ این فایل در بسته‌های عمومی پروژه قرار نمی‌گیرد.
4. نسخه Service Worker را مطابق انتشار جاری بررسی کنید. راهنمای نسخه جاری در `DEPLOYMENT_5.0.5.md` است.
5. فقط مهاجرت SQL مربوط به نسخه‌ای را اجرا کنید که هنوز در دیتابیس اعمال نشده است؛ مهاجرت‌های قبلی را تکرار نکنید.
6. پس از انتشار، آزمون‌های `TEST_PLAN_5.0.5.md` و آزمون‌های پایه ورود، ثبت فعالیت و ثبت عدم حضور را اجرا کنید.

برای تاریخچه تغییرات به `CHANGELOG.md` و برای معماری سامانه به `../ARCHITECTURE.md` مراجعه کنید.
