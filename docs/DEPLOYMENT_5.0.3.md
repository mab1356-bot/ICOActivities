# راهنمای انتشار تجمعی نسخه ۵.۰.۳ از نسخه ۵.۰.۰

این بسته شامل تمام اصلاحات ۵.۰.۱ و ۵.۰.۲ و ۵.۰.۳ است؛ نیازی به نصب جداگانه بسته‌های میانی نیست.

## ۱. فایل‌های برنامه

1. از مخزن GitHub نسخه پشتیبان تهیه کنید.
2. تمام محتویات ZIP را با حفظ ساختار پوشه‌ها در مخزن جایگزین کنید.
3. فایل `config.js` فعلی را حفظ کنید؛ این فایل در ZIP قرار ندارد.
4. فایل `sw.js` فعلی و منتشرشده را حفظ کنید؛ فایل موجود در ZIP عمداً با نسخه ۵.۰.۳ بازنویسی نشده است.

## ۲. دیتابیس Supabase

این دستورالعمل با فرض اجرای قبلی مهاجرت پایه `supabase/5.0.0_modules_attendance.sql` نوشته شده است.

- اگر مهاجرت ۵.۰.۱ قبلاً اجرا نشده است، فقط فایل `supabase/5.0.1_attendance_time_fields.sql` را در SQL Editor اجرا کنید.
- اگر این مهاجرت قبلاً اجرا شده است، نیازی به اجرای مجدد نیست.
- فایل SQL پایه نسخه ۵.۰.۰ را دوباره اجرا نکنید.
- نسخه‌های ۵.۰.۲ و ۵.۰.۳ هیچ تغییر دیتابیسی ندارند.

## ۳. نسخه Service Worker

در فایل `sw.js` منتشرشده خودتان، فقط این دو مقدار را دستی تغییر دهید:

```js
/* نسخه: actbk-v5.0.3 */
const CACHE_VERSION = 'Ver-5.0.3';
```

سایر منطق Service Worker را حفظ کنید. مقدار `CACHE_NAME` باید همچنان از `CACHE_VERSION` ساخته شود.

## ۴. آزمون انتشار

چک‌لیست کامل در `docs/TEST_PLAN_5.0.3.md` و راهنمای تجمیعی در `docs/UPGRADE_5.0.0_TO_5.0.3.md` قرار دارد. علاوه بر آزمون‌های رابط کاربری، موارد زیر را بررسی کنید:

- مرخصی ساعتی بدون ساعت ثبت نشود.
- سایر رویدادها بتوانند با ساعت یا بدون ساعت ثبت شوند.
- رویدادهای روزهای غیرکاری در داشبورد و CSV محاسبه شوند.
- عنوان دکمه دوم «مشاهده تقویم» باشد.
- حساب ۹۵۸۰۰۱ در فرم ثبت فعالیت جدید، فرد ۷۸۴۹۵ را پیش‌فرض انتخاب کند و بتواند انتخاب را تغییر دهد.

آزمون عملی روی محیط Supabase سازمان باید پس از استقرار انجام شود.
