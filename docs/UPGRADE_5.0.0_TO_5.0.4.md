# راهنمای تجمعی نسخه ۵.۰.۴

این بسته شامل نسخه پایه ۵.۰.۰ و اصلاحات ۵.۰.۱، ۵.۰.۲، ۵.۰.۳ و ۵.۰.۴ است.

## اگر اکنون روی نسخه ۵.۰.۳ هستید

1. فایل‌های بسته را در GitHub جایگزین کنید و `config.js` را حفظ کنید.
2. مهاجرت `supabase/5.0.4_attendance_multiday_time_range.sql` را یک بار اجرا کنید.
3. `CACHE_VERSION` در فایل `sw.js` منتشرشده را دستی به `Ver-5.0.4` تغییر دهید.
4. چک‌لیست `docs/TEST_PLAN_5.0.4.md` را اجرا کنید.

## اگر دیتابیس فقط مهاجرت پایه ۵.۰.۰ را دارد

1. ابتدا `supabase/5.0.1_attendance_time_fields.sql` را اجرا کنید.
2. سپس `supabase/5.0.4_attendance_multiday_time_range.sql` را اجرا کنید.
3. SQL پایه ۵.۰.۰ را دوباره اجرا نکنید.

## تغییرات تجمیعی

- ۵.۰.۱: بازطراحی درگاه ماژول، انتخاب بعد از ثبت اقدام، ساعت رویدادهای عدم حضور و گزارش روزهای غیرکاری.
- ۵.۰.۲: عنوان دکمه «مشاهده تقویم».
- ۵.۰.۳: انتخاب پیش‌فرض فرد ۷۸۴۹۵ برای حساب ۹۵۸۰۰۱ فقط در فرم ثبت فعالیت.
- ۵.۰.۴: انتخاب ساعت ۲۴ ساعته مشترک، ترتیب تاریخ/ساعت در فرم عدم حضور، پشتیبانی از ساعت مرزی در بازه چندروزه و تفکیک روزانه کاری/غیرکاری در داشبورد و CSV.

## فایل‌های حساس استقرار

- `config.js`: فایل فعلی خود را حفظ کنید؛ در بسته وجود ندارد.
- `sw.js`: فایل منتشرشده خود را حفظ کنید و فقط نسخه کش را دستی به ۵.۰.۴ ارتقا دهید.
- دیتابیس: مهاجرت‌های لازم را مطابق وضعیت فعلی Supabase اجرا کنید.
