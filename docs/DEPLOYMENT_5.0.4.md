# راهنمای انتشار نسخه ۵.۰.۴ از نسخه ۵.۰.۳

## ۱. پشتیبان‌گیری

- از مخزن GitHub نسخه پشتیبان تهیه کنید.
- پیش از مهاجرت، از جدول `public.attendance_events` و ساختار دیتابیس نسخه پشتیبان تهیه کنید.

## ۲. جایگزینی فایل‌ها

- تمام محتویات ZIP را با حفظ ساختار پوشه‌ها در مخزن جایگزین کنید.
- فایل `config.js` فعلی را حفظ کنید؛ در بسته ارائه نشده است.
- فایل `sw.js` منتشرشده فعلی را حفظ کنید؛ این فایل عمداً در بسته بازنویسی نشده است.

## ۳. مهاجرت Supabase

با فرض اینکه نسخه ۵.۰.۰ و مهاجرت ۵.۰.۱ قبلاً اجرا شده‌اند، فقط این فایل را یک بار در SQL Editor اجرا کنید:

`supabase/5.0.4_attendance_multiday_time_range.sql`

این مهاجرت قید `attendance_hourly_fields` را تغییر می‌دهد تا در رویدادهای چندروزه ساعت پایان از نظر مقدار ساعت شبانه‌روز الزاماً بزرگ‌تر از ساعت شروع نباشد. در رویداد یک‌روزه و مرخصی ساعتی، ساعت پایان همچنان باید بعد از شروع باشد.

SQL نسخه‌های ۵.۰.۰ و ۵.۰.۱ را مجدداً اجرا نکنید.

## ۴. نسخه Service Worker

در فایل `sw.js` منتشرشده خودتان، فقط این مقادیر را دستی به‌روزرسانی کنید:

```js
/* نسخه: actbk-v5.0.4 */
const CACHE_VERSION = 'Ver-5.0.4';
```

منطق دیگر Service Worker را حفظ کنید.

## ۵. آزمون پس از انتشار

چک‌لیست `docs/TEST_PLAN_5.0.4.md` را اجرا کنید. به‌ویژه یک رویداد سه‌روزه با ساعت شروع ۱۵:۰۰ در روز اول و ساعت پایان ۰۸:۰۰ در روز سوم ثبت و گزارش روزانه آن را بررسی کنید.

آزمون عملی دیتابیس باید پس از اجرای SQL در پروژه Supabase واقعی انجام شود.
